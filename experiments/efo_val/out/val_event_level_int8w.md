# 1527 帧验证集 · 事件级评估（真实数据）

数据：**15 个序列 / 1527 帧**，逐帧真值来自标注文件；判据 conf=0.5、k_in=3、m_out=5；状态机为 `packages/efo/generate_events`（与系统同源）。

## 一、先说数据边界（重要）

导出时发现：**15 个序列的每一帧都带导丝标注**，即验证集是一个「导丝在场」片段集，不含空帧、不含完整手术起止。因此本实验：

| 能证明 | 不能证明 |
|---|---|
| 入画事件在 1527 帧真实数据上是否被检出 | 结构性盲区（无短动作段可测） |
| 入画时刻的确认延迟是否符合 (k_in−1)·Δt | 离画事件与闭合滞留时长（序列末尾截断） |
| 检测器内部空档是否会造成伪离画 | 真实量化下的事件级崩坏（需 INT8 权重） |

## 三、入画确认延迟（真实数据验证 P1 的机制）

检测到的入画时刻相对序列首帧的滞后：中位 **2 帧**（区间 2–2 帧）= **133.3 ms**。
闭式解预测 (k_in−1)·Δt = 133.3 ms。
→ 这是「入画时刻不是第 1 帧，而是第 k_in 帧」在真实数据上的直接体现：**系统报出的时间戳天然比真实开始晚 (k_in−1) 帧**，材料里必须说清这是判据性质而非误差。

## 六、结论与下一步

1. 在真实 1527 帧上，事件的**生成**是确定的：不该有的重复入画与伪离画可以逐条核对。
2. 入画时刻的滞后与闭式解一致 —— 说明「事件时间戳需要校正」不是猜的。
3. 要补的两件事：① 负样本 / 完整手术序列（才能测盲区与离画）；② 真实 INT8 权重（才能把「量化崩坏」从仿真升级为实测）。
